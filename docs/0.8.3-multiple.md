# Multiple emplacements: 0.8.3

PLMGs owns multiple persistent descriptors in a target-ID registry and at most one active inventory transaction. Each descriptor retains target ID/name/section, source weapon section/condition, actor identity, level and root position. Pickup selects the currently targeted eligible descriptor; the hold handler supplies the expected target ID/name again before return creation. No nearest-gun fallback, refund of unknown objects or shared ammunition pool is used.

Native readiness/anchors are indexed per client ID with name/section checks. A second net_spawn_after resets only its own slot, and a failure or stale client does not disable another gun. Readiness is rebuilt from native spawn on coming online. No all-ID scan or arbitrary gun-count cap remains. The serial transaction guard still prevents overlapping source removal/return initialization.

The existing preparing/consuming/returning/removing_mount/rollback journal remains flat and runs for one gun. Active descriptors leave that journal and enter the deployed registry; failed returns put only their selected descriptor back. Other guns stay deployed. Their server objects persist offline/on other levels. Registry pruning reacts only to confirmed server absence, with no refund; identity reuse suspends further transactions rather than deleting unrelated objects.

plmg_transfer version 2 stores a dense array of active descriptors plus optional pending record and invalid flag. Restore validates the whole registry before accepting it, rejects duplicate IDs/names, sparse arrays and malformed records, and imports version-1 pending/active/returning records without spawning anything. Save order is deterministic by target ID. If the registry and journal are empty and valid, it writes version-1 idle state to permit downgrade after complete pack-up. Never downgrade a save that still has emplacements or pending transfers; older releases cannot understand version 2.

Placement/confirmation rejects centers within 1.5 m of an existing recorded emplacement on the current map. This avoids stacking anchored tripods. Standing-space and exit checks remain STATIC-only and do not constitute a capsule sweep or guarantee all moving-object clearance. Model bytes, native anchoring, aiming profiles, reload consumption and 2.5-second hold behavior are inherited from accepted 0.8.2.

Native regression coverage to maintain: several simultaneous same/mixed models, independent ammo/condition, reordered pickups, saved in-flight transactions, level transitions, and legacy save import. Source fixtures and liblua5.4 do not execute native X-Ray lifetime, serialization or physics. The user accepted the multiple-emplacement candidate on 2026-10-15; its gameplay files are unchanged in the release. The supplied log shows multiple PKM/MG42 spawns without PLMG errors. This does not independently verify every regression scenario above. The separately preserved CtZ API experiment is not included.
